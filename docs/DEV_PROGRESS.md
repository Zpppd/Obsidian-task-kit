## 🏗️ 架构演进规划

### **当前架构（方案1）**

```
main.ts
├─ TaskParser (服务层)
│   ├─ shouldSkipFile() ← 公共方法
│   ├─ parseFile()
│   └─ parseAllFiles()
├─ TimeTrackerService (服务层)
└─ TaskPanelView (视图层)
    ├─ loadTasks() → 调用 taskParser.shouldSkipFile()
    └─ UI渲染
```

**优点**：
- ✅ 简单直接
- ✅ 快速实施
- ✅ 解决当前问题

**缺点**：
- ❌ 数据访问分散
- ❌ 难以扩展高级查询
- ❌ 不支持缓存和性能优化

---

### **目标架构（方案3 - TaskManagerService）**

```
main.ts
├─ FileFilterService (可选)
│   ├─ shouldSkipFile()
│   └─ getValidMarkdownFiles()
├─ TaskManagerService (核心数据层) ⭐ 新增
│   ├─ loadAllTasks() ← 统一入口
│   ├─ refreshSingleFile(file)
│   ├─ getTasksByStatus(status)
│   ├─ getTasksByTags(tags[])
│   ├─ searchTasks(query)
│   ├─ getStatistics()
│   └─ tasksCache: Map<string, Task[]>
├─ TaskParser (降级为纯解析工具)
│   ├─ parseFile()
│   └─ parseLine()
├─ TimeTrackerService (服务层)
└─ TaskPanelView (视图层 - 轻量化)
    ├─ loadTasks() → 调用 TaskManagerService
    └─ UI渲染
```

**优势**：
- ✅ 职责清晰，易于维护
- ✅ 高度可扩展，支持复杂查询
- ✅ 内置缓存，性能最优
- ✅ 支持多视图共享数据（列表、看板、日历）

**实施时机**：
- 🎯 **现在是最佳时机**：功能少，依赖简单，重构成本低（6-8小时 vs 未来20-30小时）

   - 改进：在功能设计阶段就考虑数据管理层
